# AERO deployment and local development

## 1. Install local dependencies

Install dependencies and start the API:

```powershell
python -m pip install -r requirements-dev.txt
pnpm install
```

## 2. Run locally with Firestore Emulator

Open two PowerShell windows. Start Firestore first:

```powershell
.\start-emulator.ps1
```

Then start the API and static front end:

```powershell
.\start-api.ps1
```

Open `http://127.0.0.1:8000/AERO.html`. The Emulator UI is at
`http://127.0.0.1:4000`. The API refuses to start when the Emulator is absent.

Run all automated tests with a temporary clean Emulator:

```powershell
.\test-local.ps1
```

## 3. Netlify front end

Netlify publishes `geo_` according to `netlify.toml`. Configure this Netlify
environment variable after the Render API has a public origin:

```text
AERO_API_BASE_URL=https://aero-api.onrender.com
```

The build validates that this is an exact HTTPS origin and generates
`geo_/config.js`. The committed local version stays same-origin.

## 4. Render API

Create the service from `render.yaml`, then configure:

- `GOOGLE_CLOUD_PROJECT`: production Firebase/Google Cloud project ID.
- `GOOGLE_APPLICATION_CREDENTIALS`: path to a Render secret file containing the service-account JSON.
- `AERO_ALLOWED_ORIGINS`: exact Netlify production origin, with no trailing slash.
- `AERO_ADMIN_TOKEN`: generated by Render; keep it outside source control.
- `AERO_ENV`: `production`.
- `AERO_SERVE_FRONTEND`: `false` because Netlify serves the front end.

The health check is `/health`. Do not deploy with `AERO_STORAGE=json`.

## 5. Create the production Firebase project

Authenticate interactively first:

```powershell
.\node_modules\.bin\firebase.CMD login
```

Choose a globally unique, permanent project ID. Preview the protected setup:

```powershell
.\setup-firebase-production.ps1 -ProjectId your-aero-project-id -WhatIf
```

Then run it without `-WhatIf`. The script creates a Standard `(default)`
Firestore database in Taiwan (`asia-east1`), enables delete protection, and
deploys the deny-all browser rules and indexes. The Firebase CLI officially
supports `projects:create` and `firestore:databases:create` for these steps.

If project creation succeeds but a later step fails, do not create the project
again. Resume from Firestore creation with:

```powershell
.\setup-firebase-production.ps1 -ProjectId your-aero-project-id -Resume
```

After creation, make a dedicated service account with the minimum Firestore
read/write role needed by the Render backend. Store its JSON as a Render Secret
File and point `GOOGLE_APPLICATION_CREDENTIALS` to that mounted path. Never add
the JSON file to this repository.

## 6. AI-generated course details (planned)

Generate course content before a study run, review it, and freeze a version. Do not generate
different copy live for each participant because that introduces an uncontrolled variable.

Suggested course document fields:

```json
{
  "course_id": "stable-id",
  "source": {"title": "", "url": "", "provider": ""},
  "generated": {
    "summary": "",
    "learning_outcomes": [],
    "audience": [],
    "syllabus": [],
    "model": "",
    "prompt_version": "",
    "generated_at": ""
  },
  "review": {
    "status": "draft",
    "reviewed_by": "",
    "reviewed_at": ""
  },
  "content_version": 1
}
```

Only records with `review.status = approved` should be shown to participants.
